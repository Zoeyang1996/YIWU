# 技术方案建议

状态：本文件保留开发前建议。2026-09-27 实际采用原生 DOM + TypeScript + Vite + Three.js，未引入 React；运行、构建与浏览器检查已完成，详见 README 和开发进度。以下未被实现的建议不代表完成事实。

## 初始技术选择

建议 React 处理页面与商品界面，TypeScript 约束数据，Vite 提供开发构建，Three.js 负责三维场景。优先直接使用 Three.js；是否引入 React Three Fiber、相机控制或动画库，由具体实现需求决定，不同时搭建两套渲染架构。

初始化时选择一套包管理器并提交其锁文件。Node.js 版本、实际安装版本、开发及检查命令应在成功运行后写入 README，不预填未经验证的命令结果。

## 建议的代码组织

应用初始化时再创建实际模块：`src/app` 管理导航和全局状态，`src/scenes` 管理首页与市集，`src/components` 管理界面，`src/data` 管理商品摊位配置，`src/types` 管理共享类型。按实际规模拆分，不先生成大量空实现。

## 状态与输入

首页时间状态包含当前时段、目标时段及过渡进度。街道交互包含漫游、走向摊位、相机过渡和摊位浏览。商品详情及购物车作为上层界面状态存在，上层打开时暂停下层输入。关闭面板后恢复进入前的相机、角色位置与列表滚动位置。

建议市集地址为 `/market/noon`、`/market/night`、`/market/morning`。独立地址与浏览器返回需一起验证，部署时应配置单页应用路由回退。

## 数据边界

- 市集：时段 ID、环境配置、出生点、摊位列表。
- 摊位：稳定 ID、NPC、位置、交互点、相机观察点、商品 ID 列表。
- 商品：稳定 ID、标题、图片、可选模型、规格、价格与展示说明。演示价格显式标注。
- 购物车：商品 ID、规格 ID、数量、来源市集；使用稳定数据而非三维对象。金额计算使用整数最小货币单位，统一格式化显示。

模拟版可用本地存储持久化购物车，包含数据版本和损坏数据兜底；真实交易不得将本地价格或库存视为权威。

## 三维资产和性能

首页用简化模型组合，街景用可复用模块，商品详情按需加载展示模型。优先几何体原型，逐步换成 GLB 资产。重复灯具尽量复用材质与几何体，避免每盏灯都成为带阴影的实时光源。

模型与材质的精度、灯光、纹理预算、加载时长及目标帧率须基于目标设备实测。不得把旧稿中“移动端不能用实时阴影”等绝对表述作为引擎能力事实。

场景退出时清理所属资源和监听器，注意共享资源仍有其他使用者。异步加载完成后需检查原页面是否仍在使用该资源，避免切换后旧场景重新出现。

## 与旧 Demo 的关系

旧 Demo 可以提供摊主数据和交互思路，但其运行状态未经验证。移植前应比较新版需求和现有实现；不要整体复制旧依赖、构建输出或 node_modules 到本仓库。
