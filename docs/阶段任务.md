# 阶段任务

按顺序推进，每个阶段都应提供可以观看或操作的结果。完成实现后先记录技术检查，再由用户验收体验。下面的数量是原型范围建议。

| 编号 | 范围 | 完成条件 | 当前状态 |
| --- | --- | --- | --- |
| T00 | 项目资料与 AI 工作基础 | 文档、规则、目录及参考资料齐备 | 文件准备完成 |
| T01 | 可运行技术起点 | 占位场景可打开，正交相机与尺寸适配正常，有真实启动说明 | 源文件已建立；缺 Node/npm，运行待验证 |
| T02 | 首页三时段变化 | 同一牌楼主体，滚轮和按钮切换午夜早，支持反向和快速输入 | 未开始 |
| T03 | 夜市街道灰盒 | 一段浅弯主街，角色可往返，碰撞与主要遮挡可处理 | 未开始 |
| T04 | 一个完整摊位 | 接近摊位、运镜、右侧列表、关闭返回全部连贯 | 未开始 |
| T05 | 商品详情与购物车 | 至少一件三维商品，规格与数量可选，购物车计算正确 | 未开始 |
| T06 | 三市导航与模拟结账 | 独立市集地址、返回首页、购物车跨市保留、模拟订单明确 | 未开始 |
| T07 | 正式美术样板 | 三组差异明显的夜市摊位，NPC 与商品关联，保留可用交互 | 未开始 |
| T08 | 扩展与交付 | 午早市差异化、目标设备检查、演示视频素材及正式设计说明 | 未开始 |

## T01 的范围

检查环境并初始化应用，不直接实现商城、完整三时段动画或大量摊位。通过简单几何体建立空间比例，在初始化前确定代码是否放在仓库根目录；建议根目录直接承载单一前端应用，避免再次套一层 demo 文件夹。

## T02 的范围

先实现时间状态和环境、灯具、少量陈设变化，再处理复杂美术。首屏默认午市和午夜早顺序是当前建议；若用户调整，只变更配置与相关设计记录。

## T03 至 T05 的重点

先保证一个完整的逛摊流程，再复制内容。角色移动、相机状态、界面输入和返回位置应一起验证。不要以大量静态摊位替代尚未打通的交互。

## 扩展条件

进入正式美术扩展前，应能从首页入夜市、走到摊位、看商品、加入购物车并返回。真实支付、多人在线、复杂解谜和大世界不属于当前原型范围。
